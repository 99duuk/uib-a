# 확인 항목과 알려진 범위

## 생성할 때마다 확인

`node scripts/verify.mjs <HTML> [evidence-directory]`는 HTML을 다른 임시 폴더에 복사한 뒤 오프라인 Chromium에서 검토합니다. 각 entry의 실제 viewport, 가로 넘침, 이미지 로드, Before 타일, 선택 정보, 삭제와 레이아웃 재배치, 부모/자식 복원, 되돌리기, 화면 이동 후 유지, 저장·재열람·새로고침, 전체 화면 복원, Before 마스크, 외부 검토 UI의 320/390/768/1440 너비, 100% 배율과 외부 HTTP 요청 여부를 확인합니다.

출력은 `verification.json`, 화면별 PNG, 저장본 HTML입니다. 실패 시 `failure.json`과 캡처를 남깁니다. 자동 확인은 제목/요소를 갖춘 정적 시안을 대상으로 하며, root만 있는 빈 페이지에는 삭제 시나리오가 적합하지 않습니다. 해당 경우 요구한 빈 상태의 의미 있는 안내 요소를 작성하거나 검증 범위를 따로 기록합니다.

추가로 실제 화면 이미지를 보고 다음을 확인합니다.

- [After 설계 기준](product-design.md)에 따른 정보·동작·밀도·브랜드 근거 검토
- 획일적인 카드 묶음·장식용 영문·추상적인 안내·임의 아이콘·가짜 수치 여부
- 디자인 판정과 기능 점검 결과 구분; 자동 점검 통과만으로 시각 완성 주장 금지

- Before 근거가 진짜 캡처인지, 샘플이면 샘플 표시가 있는지
- 브랜드 적합성·여백·정보 위계·주요 동작·필수 문구 유지
- PC 표/탐색 구조와 모바일 줄바꿈·스크롤·버튼 위치
- 모달·sticky·내부 스크롤·긴 문구의 하이라이트와 조작
- 클릭·터치·키보드, disabled 요소의 목록 선택과 복사 대체 경로
- 저장본에서 선택/삭제/복원을 다시 할 수 있는지
- 이전 ID가 개정된 다른 요소에 잘못 적용되지 않는지
- 추출→수정→revision 증가→재생성이 가능한지

## 릴리스 확인

패키지에 실제 프로젝트 캡처·인증 파일·절대 사용자 경로가 없는지 확인합니다. 새 위치에 설치하고 그 위치의 스크립트로 데모를 생성합니다. 스킬 구조는 skill-creator의 quick_validate.py가 사용 가능하면 확인합니다. 패키지는 MIT 라이선스를 포함하며, GitHub 업로드는 패키징과 별개입니다.

## 한계

- 브라우저 도구는 Chromium 기준입니다. Safari/Firefox/실제 iOS·Android·Windows·Linux에서 확인했다고 추정하지 않습니다.
- 현재 데모는 가상 브랜드의 기능 예시입니다. Dribbble 순위·실제 반응 지표·전환율 상승을 입증하지 않습니다. 실제 작업 시 새로 조사합니다.
- Before는 픽셀 캡처입니다. CSS transform/가려짐이 복잡한 화면은 사각 영역 맵의 한계를 시각적으로 확인하고 필요한 경우 수동 영역을 제공합니다.
- 상세 인스펙터를 붙이는 기능은 키를 작성한 After DOM에 적용됩니다. 임의의 웹사이트를 완전한 편집 가능한 앱으로 자동 변환하지 않습니다.
- PDF/PNG 일괄 내보내기·실서비스 쓰기·GitHub 자동 게시·분석 도구 계측은 이 버전의 기능이 아닙니다.

검증 결과는 각 산출물의 보고서가 근거입니다. 이 문서의 기능 목록을 모든 프로젝트에서 이미 검증된 결과로 인용하지 않습니다.
