# After 설계 기준

## 시작점

화면을 꾸미기 전, 산출물의 작업 메모에 아래 항목 기록. 서비스 UI 안에 설계 설명 삽입 금지.

- 사용자: 역할·사용 상황·사용 빈도
- 다음 행동: 이 화면에서 끝내려는 구체적인 일
- 필요한 정보: 판단에 필요한 필드·수치·상태·문구
- 현재 문제: 실제 Before에서 확인한 탐색·비교·입력의 불편
- 유지할 정체성: 기존 색·서체·이미지·밀도·어조와 근거
- 변경 이유: 어떤 정보를 더 쉽게 찾거나 어떤 행동을 더 빨리 수행하게 되는지

예: `관리자가 검토 대기 프로젝트를 찾아 담당자와 기한 확인 → 프로젝트 행 가까이에 검토 동작 배치, 상태·담당자·기한 열 정렬`. `감각적인 대시보드`, `프리미엄한 경험`, `AI 티 제거`만으로 설계 완료 처리 금지.

## 참고 선정

- 동일한 화면 과제·정보량·사용 기기의 참고부터 비교
- Dribbble 반응 지표는 후보 선정의 보조 근거
- 가능하면 실제 서비스 화면·제품 문서에서 목록 길이·상태·조작 위치 확인
- 채택 이유와 제외 이유를 함께 기록
- 참고의 글꼴·색·둥근 정도를 프로젝트에 일괄 이식하지 않음
- 목업 보드의 기울어진 기기·배경 그래픽·거대한 여백을 앱 레이아웃으로 해석하지 않음
- 접근하지 못한 이미지의 시각적 분석·확인하지 못한 반응 수치 생성 금지

## 화면 구성

| 결정 | 기준 |
| --- | --- |
| 정보 순서 | 사용자가 다음 행동을 결정하는 순서 |
| 목록·표 | 여러 항목의 동일 속성을 비교하는 과제 |
| 카드 | 개별 항목의 묶음·독립 동작·드래그 등 분리 이유가 있는 경우 |
| 여백 | 제목·본문·동작의 관계와 터치 영역을 구분하는 용도 |
| 강조 | 현재 상태·주요 동작·읽어야 할 정보에 연결 |
| 이미지 | 상품·책·장소 등 식별할 대상이나 실제 브랜드 표현 |
| 색·서체 | 기존 정체성 및 가독성 근거 |

수치가 3개라는 이유로 동일한 KPI 카드를 만들지 않음. 모든 구역에 배경색·테두리·그림자를 동시에 붙이지 않음. 관련 데이터는 열 정렬·구분선·타입 크기로 먼저 묶고 필요 시 컨테이너 적용.

내용이 적은 화면의 빈 공간은 허용. 공간을 채우기 위한 가짜 그래프·활동 목록·사용자 아바타·시각·날짜·할인·리뷰 추가 금지. 가상 데이터가 필요한 별도 시안은 샘플 범위를 명시하고 Before와 비교 조건 일치.

큰 반경·그라디언트·선명한 색·표현적인 서체 자체의 금지 아님. 브랜드와 사용 맥락에 근거한 경우 사용. 모든 프로젝트를 흑백·표·작은 글씨로 만드는 방식도 피할 것.

## 문구

- 사용자의 언어와 서비스 용어 유지
- 제목: 화면이 담은 대상·작업명
- 버튼: 수행할 동작·대상
- 설명: 상태·조건·결과 중 사용자가 알아야 할 사실
- 숫자: 의미·단위·기간을 함께 표시
- 설명을 지워도 행동에 지장이 없으면 제거 여부 검토

| 추상적·장식적 문구 | 실제 문맥이 있을 때의 대안 |
| --- | --- |
| YOUR WORK, AT A GLANCE | 프로젝트 개요 |
| NEEDS YOUR ATTENTION | 검토 대기 |
| 오늘도 나만의 속도로 읽어요 | 128 / 240쪽 |
| 시작하기 → | 표지 시안 검토 / 이어서 읽기 |
| 더 스마트한 멤버십 경험 | 누적 도장·쿠폰 사용 조건 등 확인된 정보 |

위 대안은 해당 과제가 존재할 때만 사용. 한국어 화면의 장식용 영문 소제목, 모든 버튼 뒤의 화살표, 반복되는 응원 문구를 기본 패턴으로 삽입하지 않음. 기존 서비스의 실제 브랜드 문구는 의도와 기능을 확인해 유지 가능.

## 시각 요소

- 기존 아이콘이 있으면 같은 세트 사용
- 아이콘이 필요하면 의미와 선 굵기가 일관된 SVG 사용
- 기능 이름 옆의 임의 유니코드 기호·장식 배지 제거
- 책·상품 표지는 대상을 식별하는 크기로 배치; 단순 확대 장식 지양
- 폰트·시각 자산 교체 전 사용 권한·로컬 포함 방식 확인
- 실제 콘텐츠가 없는 자산은 placeholder로 명시; 가짜 성과·권위의 근거로 사용 금지

## 모바일·PC

- 모바일: 첫 화면에서 주요 작업 확인, 충분한 터치 영역, 짧은 열·행 구조
- PC: 탐색 위치 유지, 반복 정보의 열 정렬, 업무에 맞는 행 밀도
- 좁은 화면의 표: 항목명·상태·담당자·기한의 관계가 유지되는 목록으로 재배치 가능
- 중요한 필드·기능을 숨겨 반응형 문제를 해결하지 않음
- 320·390px 모바일 및 요청된 PC viewport에서 실제 줄바꿈·스크롤 확인

## 전달 전 시각 검토

실제 viewport 캡처와 Before/After 비교 화면을 모두 확인.

1. 주요 행동: 첫 화면에서 대상과 동작을 찾을 수 있는지
2. 정보 근거: 추가한 숫자·라벨·설명이 원본 또는 명시된 fixture에 존재하는지
3. 배치 이유: 각 구역이 작업·데이터 관계로 설명되는지
4. 밀도: 반복 카드·큰 제목·여백 때문에 필요한 정보가 밀려나지 않는지
5. 장식: 영문 소제목·화살표·배지·배경 면이 실제 역할을 갖는지
6. 정체성: 로고를 가렸을 때도 콘텐츠와 사용 방식이 해당 서비스로 읽히는지
7. 예시 복제: 다른 업종에도 동일한 구성·문구·색을 그대로 적용한 것은 아닌지
8. 상태: 긴 제목·빈 결과·실패·확인창 등 요청된 상태에도 구조가 유지되는지

실패한 항목은 요소 삭제·통합·재배치 후 재확인. CSS로 `AI 느낌`을 점수화하거나 검증 스크립트 통과를 디자인 완성으로 대체하지 않음. 전달 메모에는 구체적 변경 이유와 남은 한계만 기록.

사용자가 특정 예시를 지목해 반복적으로 거부한 경우, 색·반경·문구 수정 전에 화면 구성 가정부터 재검토. 예: Fieldwork의 `현황 요약 → 안내 배너 → 표`를 유지한 채 카드를 없애는 수정은 부족. 실제 과제인 표지 검토를 중심에 두고 목록·문서·의견 작성의 관계를 다시 설계. 해당 구성을 다른 서비스의 새 기본 템플릿으로 일반화하지 않음.
