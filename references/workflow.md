# 조사·시안 제작 흐름

## 프로젝트 파악

먼저 로컬 지침, 화면 경로, 브랜드 토큰, 공통 컴포넌트, 사용자 역할과 상태 규칙을 읽습니다. 실제 동작의 기준은 현재 코드·명세·화면이며 이전 시안은 공통 검토 포맷과 확정된 선호의 참고 자료입니다. 이름·경로·프레임워크·개발 포트를 다른 프로젝트에 그대로 이식하지 않습니다.

범위 표에는 `화면 / 역할 / 상태 / viewport / variant / Before 근거 / 진행 상태`를 기록합니다. 고객 홈만 요청하면 그 범위로 시작하며, 나머지 화면 요청 시 기존 엔트리에 추가합니다. 없는 화면을 임의로 완성으로 표시하지 않습니다. 가격·약관·동의·운영 상태·주요 기능은 유지하고 실제 정보가 없으면 샘플임을 밝힙니다.

## Dribbble 참조

1. 작업 시점에 웹 검색으로 관련 화면 유형을 찾고 원본 디자인 이미지를 열어 확인합니다. 예: membership dashboard mobile, admin dashboard desktop, loyalty card app.
2. 화면 과제·정보량·상태의 적합도를 먼저 확인하고 공개 반응 지표를 보조 근거로 사용합니다. 검색 순서만으로 인기 순위를 주장하지 않습니다. 높은 반응을 얻은 홍보용 목업도 실제 업무 화면에 맞지 않으면 제외합니다.
3. 선택한 참조마다 URL·제작자·제목·관찰 시각·보이는 지표·추출 원칙·서비스 적용 위치를 남깁니다. 지표가 보이지 않으면 `null`, 제한 사유를 기록합니다. 전체 서비스 순위 또는 매출 개선을 보장하지 않습니다.
4. 이미지를 직접 볼 수 없다면 텍스트 검색 결과만으로 시각적 분석을 했다고 하지 않습니다. 접근 가능한 참조로 진행하거나 사용자가 제공한 이미지를 사용하고 제한을 표시합니다. 로그인·유료 접근·사이트 차단을 우회하지 않습니다.

`research` 항목 예시:

```json
{
  "title": "Observed reference title",
  "author": "Creator name",
  "url": "https://dribbble.com/shots/REFERENCE-ID",
  "observedAt": "ISO-8601 timestamp",
  "metrics": {"likes": null, "views": null},
  "limitations": "Public counters unavailable",
  "principles": ["Keep the current reading position beside the continue button"],
  "rejected": ["Large promotional cover area that pushes the reading action below the fold"],
  "appliedTo": ["customer-home-mobile"]
}
```

위 문자열은 형식 예시이며 실제 조사값으로 복사하지 않습니다. 원본 이미지의 재배포 권한이 없다면 결과물에는 링크·작성자·분석을 남깁니다. 원본 로고·일러스트·화면을 그대로 합성하는 대신 구조·여백·크기 관계를 서비스 자산으로 다시 작성합니다.

## 브랜드 재구성

After 작성 전 [설계 기준](product-design.md)의 작업 메모와 시각 검토 적용. 프로젝트에서 확인한 사용자 행동·필드·상태를 배치 근거로 사용. 묶음 예시의 색상·카드 구조·문구를 다른 프로젝트에 기본값으로 적용하지 않음.

`brand`에는 발견한 색·글꼴·간격·모서리·텍스트 톤·정보 밀도·유지할 요소·가정의 출처를 기록합니다. 참조 색상을 프로젝트 브랜드로 착각하지 않습니다. 기본은 정보 구조·주요 배치를 유지한 정돈이며, 사용자가 레이아웃 재구성을 원할 때 `recompose-layout`로 명시합니다.

모바일은 핵심 과제와 손가락 조작, PC는 탐색 구조·넓은 표·작업 밀도·지속 표시되는 상태를 고려합니다. 로고만 바꿔 다른 업종에 재사용할 수 있는 화면이라면 정보 구성과 문구부터 재검토합니다. 불필요한 카드·영문 장식·추상적인 설명·가짜 지표를 덜어낸 뒤 실제 캡처와 After를 비교합니다. 변화가 필요한 브랜드에는 색·이미지·큰 서체를 사용할 수 있으며, 서비스의 근거를 함께 기록합니다.

## Before·상태·전달

- 가능하면 로컬 실행 앱 또는 승인된 미리보기에서 캡처합니다. 네트워크 데이터와 토큰은 결과물에 포함하지 않습니다. fixture의 민감한 표시 데이터는 캡처 전에 가명화합니다.
- 캡처 이미지를 얻지 못하면 `missing`, 이미지만 있으면 `image`, 사람이 영역을 지정하면 `manual`로 표시합니다. 추측으로 만든 화면을 실제 Before로 표기하지 않습니다.
- 모든 엔트리는 화면·상태·viewport·variant 조합이 구분되어야 합니다. 모달, 빈 결과, 오류 등 중요한 상태를 별도 엔트리로 기록합니다.
- 결과 전달에는 정확한 절대 HTML 경로, 범위, 실제 수행한 검증, 누락·한계를 포함합니다. Desktop 복사는 요청된 경우 수행하며 원본은 보존합니다.

## 반복 수정

사용자가 저장한 HTML을 우선 데이터로 추출합니다. 선택 문구의 project/entry/side/revision/key를 현재 데이터와 비교합니다. 일치하지 않으면 오래된 선택으로 표시하고 현재 항목을 확인합니다. 그대로인 화면의 ID와 Before는 유지하며, 수정한 After의 revision만 증가시킵니다. 삭제 의도는 같은 ID에만 적용하고 개정으로 사라진 ID는 미해결로 남깁니다. 후속 요청이 실제 제품 구현을 포함하는지 구분해 작업 범위를 유지합니다.
